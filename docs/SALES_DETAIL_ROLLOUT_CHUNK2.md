# North Carolina — Sales Detail Rollout, Chunk 2

**November 12, 2026**

## Goal

Turn the live permit list into a useful salesperson workflow: our formatted, permit-specific project page is the **primary** click; the original government GIS record or issuing city's permit page remains a **separate source link**. Show project and builder fields that actually exist in each government's published data.

## Completed code

- `public/permit.html` — single responsive permit detail layout for all four active markets, with project, value, date, contractor, business contact when present, and distinct government source links.
- `public/index.html` — permit numbers open our own detail page. Government records appear in a secondary **Official source** column, and the builder column offers call/email actions only for valid source-published contacts. Search now includes project names, project numbers, business contact text and license fields.
- `src/collect.py` — extracts official Raleigh business phone, email, license, DBA, company address, project name, area, stories and housing units. It now also maps New Hanover's official `PROJECT`, `SQUARE_FEET` and separately labeled `PROJECT_CONTACT`; and Mecklenburg/Charlotte's `projname`, `projnum`, `numunits` fields. New Hanover's project contact is **not** labeled a builder.
- `public/data/sales_field_coverage.json` — aggregate report generated by the collector after a successful refresh, counting the actual availability of useful fields by jurisdiction without exporting extra contact details into that coverage report.
- `tests/test_sales_details.py` — ten offline tests covering field mapping, source URL provenance, missing-contact safety, user navigation, CSV contract, phone/email actions and aggregate coverage.

## CI root cause identified and repaired

The initial enriched collector refresh was blocked by a **single erroneous new test assertion**, not by a collector API failure. The GitHub Actions test diagnostics on **November 12, 2026, 21:59 UTC** ran **113 tests** and reported exactly one failure:

`test_sales_details.SalesDetailTests.test_no_contact_data_is_never_fabricated`

The assertion searched for `unverified` in the record's `verification` label; the actual, intentionally explicit label is `screened government record — not independently verified`. The behavior was correct, but the test expected the wrong wording.

This was fixed in commit `30bc894f6173a2357d10c002fd798b738ee34fbf`. CI now writes a small `public/data/ci_test_status.json` report from `src/run_tests_with_status.py`, including failing test names if a future refresh is blocked. Test failures still fail the workflow; publishing a diagnostic does not mark the build successful.
